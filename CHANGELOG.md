## [0.5.0] - 2026-09-30

The ADR-006 hub contract release (Decision 7): 0.5.0 is the reserved
`probe` gate threshold, so from this release the hub's own merge outputs
pass its own version gate.

### Added
- Contract-release round-trip tests over real binary outputs (`tests/roundtrip.rs`, merge-soundness PR 3c). The actual pipeline is exercised end to end: `probe merge` output is accepted by `probe enrich`/`probe summary`/`probe project` (the hub's own outputs pass its own Decision 7 gate — only true from 0.5.0); a real `probe project` output stays readable by summary/project but is rejected by merge/enrich on the projection predicate specifically (not the version gate); envelope-level merge idempotence modulo metadata (re-merging a merged file with one of its inputs changes neither `data` nor the deduplicated `inputs` inventory); a same-source specs merge collapses to a one-entry inventory that still validates against the executable schema.
- `probe project` recomputes enrichment on the full authoritative input graph before trimming (ADR-006 carrier preparation, P23): `prepare = enrich ∘ normalize` runs before seed matching and BFS, so a stale producer label (the Verus-shaped `f [transitively-verified] → helper [no status] → bad [failed]` regression) is repaired instead of frozen into a depth-limited view no later recomputation can fix. Seed matching runs over normalized keys on both sides (P8), closing the dotted-key regression where a legacy `f().`-keyed atom selected zero seeds after mapping endpoints were normalized at load. A distinct-real post-normalization collision rejects the input, exactly as `probe enrich` does (P8). Already-projected inputs skip preparation entirely — a view's labels are inherited, never recomputed over the trimmed graph — which `load_validated_atom_file` now makes knowable: it returns a `ValidatedAtomFile` struct carrying a `projected` flag alongside atoms and provenance (the loader previously discarded the schema string and projection block).
- Correspondence records and merge-side re-enrichment (merge-soundness PR 3b, ADR-006 Decisions 1/3). `probe merge --mappings` now attaches `maps-to`/`mapped-from` correspondence records (P13: unconditional — a dangling target warns, never skips — key-local, set-like on the `(target, confidence, method)` triple) instead of injecting cross-language dependency edges; `dependencies` is never modified. Records union through every equal-key resolution — stub replacement, real-vs-real first-wins, stub-vs-stub, real-vs-stub, and benign post-normalization collisions — and record targets are normalized like any other code-name (P8/P27). `merge_atom_maps` is now μ as P4 defines it: per-input normalization, conflict resolution, then one enrichment recomputation after all inputs are combined, so every merge output is on the carrier; `load_mappings` returns full `Mapping` records with endpoints normalized at load (`endpoint_lookup_maps` derives the seed-lookup maps for `probe project`). New raw staging primitives `merge_atom_maps_raw`/`merge_atom_files_raw` defer the single enrichment pass for multi-step pipelines (probe-aeneas) — raw means skip recomputation, not skip validation: both validate mapping confidences and correspondence-record shapes fail-closed, and the file-level `merge_atom_files_raw` additionally applies the same authority and `status-origin` validation as the public entry points (the bare-map `merge_atom_maps_raw`, like `merge_atom_maps`, cannot — callers own the envelope boundary). Law tests run against `merge_atom_maps`: associativity with mappings across groupings, identity (exact on the carrier, up to normalization+enrichment on legacy inputs), commutativity for disjoint keys, F_M idempotence and mapping compatibility, record preservation through every equal-key case, intermediate enrichment not changing selected base data, and the two-input dotted-alias evidence-selection regression. The executable schema gains `correspondenceRecord` definitions for `maps-to`/`mapped-from` with an envelope-level validation test over real merge output. Merged envelopes are stamped schema-version 3.1.
- Correspondence-record canonical form and fail-closed validation (PR 3b review; P27, ADR-006). Record dedup is by the identity triple itself — the previous exact-JSON dedup let a tied-key twin shield exact duplicates, growing the "set" union on self-merge and making merge output grouping-dependent (P4 counterexamples confirmed by test). An empty `method` is canonicalized to absent everywhere records are constructed or loaded (`""` and omission are one identity; the executable schema now requires non-empty `method`). Every recomputation boundary (`probe merge` per input, `probe enrich` via `prepare_atoms`, now `Result`-returning) rejects malformed `maps-to`/`mapped-from` shapes — non-array field, non-object entry, missing/non-string target, out-of-vocabulary confidence, non-string method, unexpected extra field — since merge re-emits these fields into schema-constrained output and a malformed field silently swallowing a union loses evidence grouping-dependently. Mapping confidences are validated against the vocabulary (`MAPPING_CONFIDENCE_VALUES`, pinned to the executable schema enum by test) at `load_mappings` and at the merge boundary. Per-input merge rejections are prefixed with the 1-based input position. `MergeStats.mappings_applied` is renamed `records_attached` (it counts attached records, 0–2 per mapping). New tests: tied-identity associativity regression, empty-method canonicalization, malformed-shape rejection matrix, CLI-level `--mappings` end-to-end (records attached, `dependencies` untouched, invalid confidence exits non-zero), and the envelope-determinism test now varies record/mapping input order. A generated-input law suite (`tests/merge_laws.rs`, adapted from the cross-model verification pass) sweeps the P4/P5/P27 laws over 11,664 generated associativity cases plus mapping-compatibility/idempotence pairs, asserts runtime record acceptance is exactly executable-schema validity (modulo the documented `method: ""` canonicalization) at every boundary and input position, and pins CLI rejection-before-writing for both record fields.

### Changed
- Provenance is deduplicated at the merge boundaries (P9, merge-soundness PR 3c): `merge_atom_files` and `cmd_merge` collapse identical `inputs` entries (first occurrence kept), making the inventory record *which* sources were composed rather than how many times, and giving envelope idempotence up to metadata. The executable schema's merged specs/proofs `inputs` `minItems` is relaxed 2 → 1, since dedup can legitimately collapse two same-source inputs to one entry.
- A post-normalization key collision within a single specs/proofs input is now warned about and counted in `stats.conflicts` instead of resolving silently (plan §6 issue 6; last-wins kept per P7 — the atoms-side analogue is already fail-closed rejection per P8).
- P8 normalization now covers the categorized dependency subsets (`requires-dependencies`, `ensures-dependencies`, `body-dependencies`, `type-dependencies`, `term-dependencies` — exposed as `CATEGORIZED_DEPENDENCY_ARRAYS`), so the P15 decomposition equality survives normalization; non-string entries pass through untouched.
- `probe project` trims the categorized dependency subsets with the same filter as `dependencies` (P15 preservation): a projection no longer carries spec-position references to atoms it excluded.
- Projection selection is pinned dependency-only (plan §8): correspondence records are never traversed, and the regression test documents that the pre-ADR-006 reachability through fabricated edges is not reproduced.
- Intra-input collision policy is now uniform rejection (P8 reconciliation, merge-soundness PR 3b). A post-normalization collision between distinct real atoms within a single input — distinctness judged modulo correspondence records, which union instead — is rejected by `probe merge` during per-input normalization, exactly as `probe enrich` already rejects it (previously merge warned and counted it in `conflicts`). Once μ re-enriches, merge's silently first-wins-selected evidence would feed enrichment inside merge — the laundering path P8 condemns at the unary boundary. Cross-input real-vs-real conflicts remain first-wins with a warning. `probe merge` also fails closed on out-of-enum `status-origin` markers, like enrich and summary (ADR-006 Decision 2).
- Enrichment recomputation and the summary consumer contract (#78, merge-soundness PR 2). `enrich_verification_status` is now a recomputation, not an upgrade pass (P23): one reverse BFS from one seed set — explicit `failed`/`unverified` atoms plus every `status-origin`-bearing atom — then every `verified`/`transitively-verified` label is set fresh, so stale `transitively-verified` labels are downgraded and imported `transitively-verified` is rewritten to `verified` unconditionally. Contamination flows through missing-status atoms (transparent by construction) and stops only at trusted boundaries (`trusted` with no `status-origin` — copied trust seeds instead of shielding). `probe summary` gains the `imported_verified` list (`status-origin: "translation"` AND verified status; translated non-verified statuses appear in no list; `kernel-taint` stays in the local partitions) and computes all partitions over code atoms — `language: "blueprint"` atoms appear in no list and are excluded from entrypoint classification. `probe enrich` applies carrier preparation (`prepare = enrich ∘ normalize`, exposed as `prepare_atoms`) so dotted-alias dependencies reach their contamination sources instead of dangling. The executable schema constrains `status-origin` to the two-value enum.
- Fail-closed hardening from the PR 2 cross-model review (#79). `probe enrich` and `probe summary` reject atoms whose `status-origin` is outside the two-value enum (`validate_status_origins` — the runtime does not schema-validate); the check sits inside the public `summarize_atoms` (now `Result`-returning) so library callers cannot get an invalid marker classified as local evidence, and enrichment's seed/trusted-boundary predicates are presence-based, so a malformed non-string marker seeds instead of silently reading as absent. A post-normalization key collision that would discard a distinct real atom is now surfaced (P8): `probe enrich` rejects the input — with one input there is no second source to arbitrate the evidence, and silent selection can launder contamination. (`probe merge` initially warned and counted it in `conflicts` with first-wins standing; superseded by the uniform rejection above, merge-soundness PR 3b.) Normalization strips *all* trailing dots (P8's stated rule; previously only one), so it is a fixed point and a repeated-dot alias (`g()..`) cannot slip a distinct atom past the collision guard.
- The ADR-006 authority boundary (#76, merge-soundness PR 3a). A shared authority validator (`src/authority.rs`) runs at every hub envelope boundary: `probe merge` and `probe enrich` reject projections in both formats (`probe/projected-atoms`, or `probe/merged-atoms` plus a `projection` field — presence-based, `projection: null` counts) and pre-contract atoms envelopes per the ADR-006 Decision 7 version gate (probe-lean < 0.16.0, probe-aeneas < 0.21.0, probe-leanblueprint < 0.11.0, probe-vcvio < 0.2.0; `probe` outside 0.5.0 ≤ v < 1.0.0, and `tool.command: "merge-atoms"` at any version). Missing/malformed `tool` metadata and unparsable `tool.version` on a gated name are rejections; unknown tool names pass. `probe summary` and `probe project` run the version-gate component only — projections stay readable there.
- `probe project` writes the distinct `probe/projected-atoms` schema (schema-version 3.1); `detect_category` recognizes it as atoms for read-only consumers.
- Executable schema: the atoms branches are keyed on provenance shape (`source` vs `inputs`), so composed producer envelopes (`probe-aeneas/extract` with `inputs`) validate as-is; added `probe/projected-atoms` (its `projection` block required) and `probe-vcvio` to the single-tool pattern, with a positive `status-origin` fixture.
